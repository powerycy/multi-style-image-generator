# 人物风格化与 360° 全景质检

本参考用于人物照片风格化、身份参考和带人物的 360° 全景图。它补充 `game-visual-styles.md`，不替代风格路由、UI、视频、空间照片或全景脚本规则。

## 1. 统一人物融合与身份优先级

用户提供人物照片并用于生成图片、360° 全景图或视频内容时，默认语义是“让同一个人自然进入目标世界”，不需要用户额外说“融入环境”。

- 默认保留身份锚点：脸型、眉眼关系、眼形、鼻唇比例、笑容、面颊轮廓、发型/发际线轮廓、体态和可识别气质。
- 默认重设计衣着、鞋履、发饰、道具、动作、材质和光照，使其符合目标风格和场景叙事；同时安排与场景有关的姿势。
- 默认安排探索、战斗、调查、劳动或互动等与场景有关的动作，不生成站立合影、旅游打卡或正面摆拍。
- 只有用户明确说“保留原衣着”“保留原发饰”“保留原姿势”“保留原道具”“不要换造型”时，才保留照片中的对应元素。
- 禁止照片抠图贴背景、现代装与幻想场景割裂、人物与环境光照不一致、照片脸粘贴到风格化身体。

人物照片作为身份参考，或用户说“用我的脸、像我本人、保留我的脸、参考这张人物照片”时，目标是让生成结果可辨认为同一个人：

- 身份相似度高于场景细节、特效和服装精致度。
- 不得把用户变成泛化游戏角色脸、网红脸、不同年龄段或另一个人的五官。
- 允许统一皮肤材质、环境光和轻微气色优化；不得改变核心五官比例。
- 人脸清晰可见时直接执行，不为默认流程频繁追问。人脸不可见、严重模糊或遮挡时，再索取清晰人脸照片。
- 模型无法稳定达到高保真身份时，区分“相似气质”和“严格像本人”，不得过度承诺。

## 2. 直接出图 prompt 标准模块

人物照片参与直接出图时，把以下内容按任务裁剪后并入最终 prompt，不要把方括号原样保留：

```text
将人物参考图作为身份参考，让同一个人自然进入目标世界与场景。身份相似度优先于场景特效和造型细节；保留脸型、眉眼关系、眼形、鼻唇比例、自然笑容、面颊轮廓、发际线、发型轮廓、体态和可识别气质。默认把衣着、鞋履、发饰、道具、动作、材质和光照重新设计为目标世界观，并安排与场景有关的姿势；只有用户明确要求时才保留原造型、姿势或道具。人物、脸、衣着、道具和背景统一重绘为同一画风、同一光照、同一边缘与材质语言。双眼自然对称，瞳孔位置协调，双眼视线同向并符合头部朝向，保持参考图中的自然表情关系。禁止泛化角色脸、网红脸、不同年龄感、斗鸡眼、内斜视、外斜视、大小眼、瞳孔错位、左右高光不一致、异常眼睑、僵硬微笑、照片脸粘贴、绿幕抠图感、硬边缘光晕、站立合影、旅游打卡姿势和人物环境光照割裂。
```

带人物的 360° 全景图再加入：

```text
360°×180° 等距柱状投影全景图，2:1 宽高比，左右边缘无缝衔接。人物大小、距离和位置根据用户意图和画面叙事自然决定：用户说“把我放进场景”时，让人物全身在主要观看方向附近舒适可辨并自然融入；用户强调主角、人物明显或脸清楚时，提高人物存在感；只有用户明确以环境为主时才适当缩小人物。人物避开顶部和底部极点、避开左右拼接缝，身体、脸和关键道具不得跨越左右边缘。四周环境、建筑、天空和远景连续展开；除非用户明确要求，不做贴近观察点的海报式特写、浅景深特写或合影构图。
```

## 3. 人脸、眼神与表情质检

出图后先在正常观看尺寸和预计交付场景中看整体，再进行不超过源图有效分辨率的适度检查。不要为了检查而过度放大远中景人物，也不要把正常观看尺寸下不可见的像素级瑕疵判为失败。

- 身份：对照脸型、眉眼关系、眼形、鼻唇比例、笑容、面颊、发际线和年龄感；“亚洲女性、微笑、扎发”等泛化标签不算身份保真。
- 双眼：自然对称，瞳孔位置协调，双眼视线同向且符合当前头部朝向。
- 禁止：斗鸡眼、内斜视、外斜视、大小眼、瞳孔错位、左右高光不一致、异常眼睑或不合理眼白。
- 表情：保持参考图中的自然笑容和表情关系，不生成僵硬微笑、陌生神情或与叙事动作冲突的表情。
- 风格统一：脸部也要进入目标画风，但不得因此改变核心五官比例；禁止直接粘贴高分辨率照片脸。

按正常观看时的实际影响判断。明显是另一个人、明显斗鸡眼或视线错位等会破坏用户目标的问题需要重绘；只有过度放大后才看见的轻微不对称或远中景脸部细节不足，不阻止交付。不因远景人物无法进行人像级身份核验而否定整张图。

## 4. 360° 全景人物布局

人物布局根据用户表达和场景叙事决定，不建立固定距离、画面占比或命名模式：

- “把我放进场景”表示人物应在主要观看方向附近舒适可辨、自然融入，不能远到失去存在感。
- “我是主角”“人物明显一点”“脸清楚一点”表示应提高人物存在感，同时保持球面观看舒适。
- 只有用户明确强调环境、建筑或空间展示时，才让人物作为较小的环境角色。
- 避开顶部和底部极点，避开左右拼接缝；身体、脸和关键道具不能跨越左右边缘。
- 不生成贴近观察点的海报式正面人物、浅景深特写或合影构图，除非用户明确要求。
- 等距柱状投影最明显的几何风险通常位于顶部和底部极点；人物过近或过大仍会在沉浸观看中显得突兀和变形。

## 5. 全景有效性与 WebGL 检查

2:1 只是文件比例，不等于严格可用的球面全景。

1. 检查尺寸是否接近 2:1；必要时使用 `scripts/run_with_deps.py normalize_equirectangular_aspect.py` 规格化。
2. 检查平面图左右边缘的颜色、结构、地平线和物体是否连续，人物或关键道具是否跨缝。
3. 检查地面、建筑、天空和远景是否形成合理的环绕空间，而不是普通宽幅图被拉伸。
4. 平面检查通过后，使用 `scripts/create_panorama_viewer.py <2:1-image-path> --embed-image` 创建 QA 预览。
5. 在 WebGL 预览中查看前、后、左、右、天顶、地面和接缝附近多个朝向，检查明显断裂、重影、拉伸、空洞或几何变形。

左右连续、空间关系合理且 WebGL 多个朝向没有影响浏览的明显问题时，可称为“可用的 360° 全景图”并直接交付。只在特定朝向可见、且不影响浏览的轻微接缝或极点拉伸不阻止交付；仅在它实质影响用户明确要求时才说明。若存在明显空间断裂、关键主体跨缝或普通宽幅图被拉伸等影响浏览的问题，则先重绘；仅修正了尺寸时只说明“只是已规格化为 2:1”，不得把比例正确等同于全景正确。

## 6. 最终交付流程

按以下顺序处理“人物照片 + 直接出图 + 360° 全景图”：

1. 识别身份参考，要求同一个人自然进入目标世界。
2. 根据用户意图和画面叙事自然决定人物存在感，生成世界观衣着、发饰、动作和环境融合的候选图。
3. 检查尺寸并在必要时规格化为 2:1。
4. 在正常观看尺寸和适度放大下检查身份、双眼、视线、表情、服装动作、光照和人物比例。
5. 检查左右连续性、空间关系，并在 WebGL QA 预览中检查多个朝向。
6. 达到用户明确创作目标且不存在正常观看时可见的明显身份、眼神、融合、变形、拼接或可用性问题时，直接交付 PNG 与 HTML。
7. 不因远景人物无法进行人像级身份核验或只有过度放大才可见的轻微瑕疵降低交付判断。限制只有在实质影响用户明确要求或成品可用性时才说明。
8. 只有明显不可用时才重绘，自动重绘最多一次；一次重绘后仍明显不可用时如实报告并等待用户决定，不自动进行第二次重绘。
9. 动态增强全景、360° 全景 HTML 和空间照片预览继承已质检底图，不在衍生阶段重新改变人物身份、造型或场景。

最终回复不得声称“已保留本人脸”，除非身份、眼神与表情质检确实通过。无法进行高保真核验时，使用“参考了人物身份”或“保留相似气质”等准确表述；只有这件事实质影响用户明确提出的人脸要求时才说明限制，不因此降低对整张图的判断。

## 7. 交付与重绘案例

直接交付：人物在主要观看方向舒适可辨，脸型、眉眼和笑容关系与参考一致；双眼视线自然；造型符合目标世界；左右边缘和 WebGL 多朝向连续。人物较远但符合用户对环境叙事的要求，也直接交付，不追加工程化质量标签。

需要重绘：现代短袖和日常长裤直接进入古代幻想场景；人物正面站立合影；正常观看时明显是陌生脸、斗鸡眼或瞳孔错位；人物远到违背“人物明显”的明确要求；身体跨越拼接缝；2:1 文件在 WebGL 中出现明显断裂或不可用的空间拉伸。
