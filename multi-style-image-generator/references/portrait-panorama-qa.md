# 人物风格化与 360° 全景质检

本参考用于人物照片风格化、身份参考和带人物的 360° 全景图。它补充 `game-visual-styles.md`，不替代风格路由、UI、视频、空间照片或全景脚本规则。

## 1. 默认人物融合与身份优先级

用户提供人物照片并要求生成图片时，默认语义是“让这个人进入目标世界”，不需要用户额外说“融入环境”。

- 默认保留身份锚点：脸型、眉眼关系、眼形、鼻唇比例、笑容、面颊轮廓、发型/发际线轮廓、体态和可识别气质。
- 默认重设计服装、鞋履、道具、姿势、动作、光照和材质，使其符合目标风格和场景叙事。
- 默认安排探索、战斗、调查、劳动或互动等与场景有关的动作，不生成站立合影、旅游打卡或正面摆拍。
- 只有用户明确说“保留原服装”“保留原姿势”“保留原道具”“不要换造型”时，才保留照片中的对应元素。
- 禁止照片抠图贴背景、现代装与幻想场景割裂、人物与环境光照不一致、照片脸粘贴到风格化身体。

人物照片作为身份参考，或用户说“用我的脸、像我本人、保留我的脸、参考这张人物照片”时，自动启用严格身份保留模式：

- 身份相似度高于场景细节、特效和服装精致度。
- 不得把用户变成泛化游戏角色脸、网红脸、不同年龄段或另一个人的五官。
- 允许统一皮肤材质、环境光和轻微气色优化；不得改变核心五官比例。
- 人脸清晰可见时直接执行，不为默认流程频繁追问。人脸不可见、严重模糊或遮挡时，再索取清晰人脸照片。
- 模型无法稳定达到高保真身份时，区分“相似气质”和“严格像本人”，不得过度承诺。

## 2. 直接出图 prompt 标准模块

人物照片参与直接出图时，把以下内容按任务裁剪后并入最终 prompt，不要把方括号原样保留：

```text
将人物参考图作为严格身份参考，让同一个人自然进入[目标世界与场景]。身份相似度优先于场景特效和服装细节；保留脸型、眉眼关系、眼形、鼻唇比例、自然笑容、面颊轮廓、发际线、发型轮廓、体态和可识别气质。默认把服装、鞋履、道具、姿势、动作、光照和材质重新设计为[目标世界观]，让人物正在执行[与场景有关的叙事动作]；只有用户明确要求时才保留原服装、原姿势或原道具。人物、脸、服装、道具和背景统一重绘为同一画风、同一光照、同一边缘与材质语言。双眼自然对称，瞳孔位置协调，双眼视线同向并符合头部朝向，保持参考图中的自然表情关系。禁止泛化角色脸、网红脸、不同年龄感、斗鸡眼、内斜视、外斜视、大小眼、瞳孔错位、左右高光不一致、异常眼睑、僵硬微笑、照片脸粘贴、绿幕抠图感、硬边缘光晕、站立合影、旅游打卡姿势和人物环境光照割裂。
```

带人物的 360° 全景图再加入：

```text
360°×180° 等距柱状投影全景图，2:1 宽高比，左右边缘无缝衔接。环境主导的中景构图；人物全身位于地平线附近，距观察点约 4–6 米，占画面高度约 10–15%。人物避开顶部和底部极点、避开左右拼接缝，身体、脸和关键道具不得跨越左右边缘。四周环境、建筑、天空和远景连续展开；不要大型近景人物、海报式居中构图、浅景深特写或合影构图。
```

## 3. 人脸、眼神与表情质检

出图后先放大人物脸部，再判断是否进入全景与 HTML 流程。不得只凭缩略图判断。

- 身份：对照脸型、眉眼关系、眼形、鼻唇比例、笑容、面颊、发际线和年龄感；“亚洲女性、微笑、扎发”等泛化标签不算身份保真。
- 双眼：自然对称，瞳孔位置协调，双眼视线同向且符合当前头部朝向。
- 禁止：斗鸡眼、内斜视、外斜视、大小眼、瞳孔错位、左右高光不一致、异常眼睑或不合理眼白。
- 表情：保持参考图中的自然笑容和表情关系，不生成僵硬微笑、陌生神情或与叙事动作冲突的表情。
- 风格统一：脸部也要进入目标画风，但不得因此改变核心五官比例；禁止直接粘贴高分辨率照片脸。

任何明显身份或眼神问题都判定为不通过。优先针对人物脸部重绘，不直接输出 HTML。

## 4. 360° 全景人物布局

用户没有明确要求人物特写时，默认使用环境主导布局：

- 人物位于地平线附近的中景，距观察点约 4–6 米，全身可见，占画面高度约 10–15%。
- 环境、建筑、天空、远景和环绕空间是主叙事，人物是自然存在于其中的角色。
- 避开顶部和底部极点，避开左右拼接缝；身体、脸和关键道具不能跨越左右边缘。
- 不生成贴近观察点的大型正面人物、海报式居中近景、浅景深特写或合影构图，除非用户明确要求。
- 等距柱状投影最明显的几何风险通常位于顶部和底部极点；人物过近或过大仍会在沉浸观看中显得突兀和变形。

## 5. 全景有效性与 WebGL 检查

2:1 只是文件比例，不等于严格可用的球面全景。

1. 检查尺寸是否接近 2:1；必要时使用 `scripts/run_with_deps.py normalize_equirectangular_aspect.py` 规格化。
2. 检查平面图左右边缘的颜色、结构、地平线和物体是否连续，人物或关键道具是否跨缝。
3. 检查地面、建筑、天空和远景是否形成合理的环绕空间，而不是普通宽幅图被拉伸。
4. 平面检查通过后，使用 `scripts/create_panorama_viewer.py <2:1-image-path> --embed-image` 创建 QA 预览。
5. 在 WebGL 预览中查看前、后、左、右、天顶、地面和接缝附近多个朝向，检查明显断裂、重影、拉伸、空洞或几何变形。

只有左右连续、空间关系合理且 WebGL 多个朝向无明显问题时，才能称为“可用的 360° 全景图”。否则只说明“只是已规格化为 2:1”，不得把比例正确等同于全景正确。

## 6. 最终交付门槛

按以下顺序处理“人物照片 + 直接出图 + 360° 全景图”：

1. 识别身份参考，启用严格身份保留与默认人物融合。
2. 生成世界观服装、叙事动作和环境主导的全景候选图。
3. 检查尺寸并在必要时规格化为 2:1。
4. 放大检查身份、双眼、视线、表情、服装动作、光照和人物比例。
5. 检查左右连续性、空间关系，并在 WebGL QA 预览中检查多个朝向。
6. 任一关键项失败时，针对失败项重绘并重新检查；不导出最终 PNG 或 HTML，也不把 QA 候选链接当作交付。
7. 全部通过后，才把对应 PNG 和 HTML 标记为最终结果；动态增强全景也只能基于通过质检的底图创建。

最终回复不得声称“已保留本人脸”，除非身份、眼神与表情质检确实通过。无法达到高保真时，说明“参考了人物身份”或“保留相似气质”，并明确限制。

## 7. 通过与不通过案例

通过：人物脸型、眉眼和笑容关系与参考一致；双眼视线自然；造型符合目标世界；人物在中景执行叙事动作；左右边缘和 WebGL 多朝向连续。

不通过：现代短袖和日常长裤直接进入古代幻想场景；人物正面站立合影；只保留泛化性别、发型和微笑而换成陌生脸；斗鸡眼或瞳孔错位；人物占据全景大部分高度；身体跨越拼接缝；2:1 文件在 WebGL 中出现断裂或拉伸。
